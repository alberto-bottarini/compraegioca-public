Come funziona l'algoritmo

Documentazione interna del sistema di classificazione dei risultati di ricerca.

Panoramica

Quando un utente cerca un gioco, i risultati provenienti dai vari negozi vengono classificati in tre bucket:

  • relevant — prodotti pertinenti alla ricerca, mostrati in cima
  • secondary — espansioni, accessori, bundle: mostrati nella sezione "accessori ed espansioni" (collassata)
  • excluded — risultati irrilevanti (prezzo < 5€, lego, puzzle, o nessun match con la query): nascosti di default

La classificazione è un unico passaggio diretto, basato solo su due blacklist lessicali.

Classificazione

Ogni risultato viene classificato individualmente:

  1. Se prezzo < 5€, o il nome contiene una parola della blacklist esclusi, o nessun token della query appare nel nome → excluded
  2. Se il nome contiene una parola della blacklist espansioni → secondary
  3. Altrimenti → relevant

Il match query usa word boundary: tutti i token della query devono comparire nel nome (ordine libero, non necessariamente adiacenti).

Blacklist espansioni (SECONDARY_RE)

Parole che identificano espansioni o accessori:

sleeve, sleeves, bustina/e, proteggi, protezioni, insert, inserto, organizer, organizzatore, playmat, tappetino, tappeto, accessorio/i, ricambio/i, portacarte, porta carte, dado, dadi, espansione/i, expansion/s, promo, promozione, booster, automa, moneta, monete, goodies

Blacklist esclusi (EXCLUDED_RE)

Prodotti completamente irrilevanti, nascosti di default (non compaiono nemmeno nella sezione espansioni):

lego, puzzle, portachiavi, pendolo, collana, culla, borsa, sacca, francobolli, plancia, map pack, dice set, super string, prophila, souvenir

Debug mode

Attivabile con ?debug=1 (cookie 24h). Disattiva con ?debug=0.

In debug mode ogni risultato mostra un badge con il motivo della classificazione:

  • secondary · 🚫 "espansione" — parola blacklistata (SECONDARY_RE)
  • relevant / excluded — nessuna parola blacklistata trovata

Limitazioni note

  • Se un'espansione è venduta senza nessuna delle parole della blacklist espansioni nel nome (naming sciatto del negozio), resta classificata relevant insieme al gioco base.
  • L'unica correzione possibile per un caso del genere è aggiungere la parola mancante a SECONDARY_RE (o EXCLUDED_RE se il prodotto è del tutto estraneo).

Nota storica: fino ad agosto 2026 esisteva anche una logica di subset demotion ed expansion tokens che inferiva la classificazione dal confronto tra i token dei nomi dei prodotti. È stata rimossa perché troppo aggressiva su titoli brevi: bastava un solo token condiviso con un item secondary per far retrocedere anche il prodotto giusto (es. il gioco base scartato perché "sottoinsieme" di un suo promo pack).
